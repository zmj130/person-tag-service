# 架构与关键取舍

## 数据职责

达梦是事实数据源：人员资料、标签定义、规则、人员标签关系、同步批次和游标全部以数据库为准。Trie 只是启用规则的内存索引，服务重启后可从数据库完整重建。

Vue 3 管理端构建为静态资源，由 Spring Boot 同源托管。浏览器直接调用 `/api` 管理接口；人工触发同步时临时输入调度 Token，前端不持久化 Token。部署仍是单个 Java 进程。

```text
管理端浏览器 -------> Spring Boot 管理接口 -------> 达梦

DolphinScheduler -> 内部同步接口 -> 远程人员 HTTP API
                                      |
                                      v
                               单页事务写达梦
                                      |
                         +------------+------------+
                         |                         |
                    外部标签绑定              Trie 规则匹配
                         |                         |
                         +------------+------------+
                                      v
                                人员标签关系
```

## Elasticsearch 的边界

达梦始终是事实库；ES 只是可删除、可重建的人员画像查询副本。它承担跨人员字段全文检索、标签 AND/OR、动态指标过滤和聚合反查，不参与标签审核、规则计算或事务判断。主配置已启用 ES、自动化测试强制关闭；只有显式调用重建接口才创建固定前缀索引，应用启动不会自动修改共享集群。索引存在后，人员、标签关系和规则结果的事务提交会触发对应人员画像的单文档刷新。

## 同步一致性

- DolphinScheduler 生成稳定 `batchNo`，重复调用成功批次直接返回原结果。
- 使用远程游标分页，不依赖两台服务器时钟一致。
- HTTP 拉取发生在事务外，每一页写入及游标推进在同一个新事务中。
- 页面失败时整页回滚；已成功页面的游标已经提交，重试从最新游标继续。
- `PT_PERSON.EXTERNAL_ID`、`PT_PERSON_TAG(PERSON_ID,TAG_ID,SOURCE_TYPE,SOURCE_REF)` 和批次号都有唯一约束。
- 当前代码的 `synchronized` 只避免单实例并发。生产 DolphinScheduler 工作流最大并行度必须设为 1；多实例部署时应再增加数据库租约锁。

## 标签来源和优先级

| 来源 | 默认状态 | 含义 |
|---|---|---|
| `MANUAL` | `APPROVED` | 管理人员明确绑定 |
| `REMOTE` | `APPROVED` | 上游系统下发 |
| `RULE` | `PENDING` 或 `APPROVED` | 结构化规则或兼容的 Trie 关键词规则生成 |

同一人员的同一标签允许人工、上游和多条规则来源同时存在，每条关系使用稳定 `SOURCE_REF` 区分；新增来源不得覆盖已有来源，撤销时也只能处理目标来源。人员详情按标签聚合展示一次，点击后下钻查看全部来源，并从达梦动态读取该人员实际存在的自定义指标，以与规则计算相同的类型口径展示布尔、枚举、日期、数值和单位，支持人工核验命中结果。人工拒绝的规则候选保留为 `REJECTED`，防止下一次同步反复生成。旧 Trie 清理只处理对应 `PT_TAG_RULE` 产生的绑定，不得删除结构化规则结果；人工修改人员资料后同时执行两类规则判断。

## 删除与生命周期

- 人工解绑只删除 `MANUAL` 来源；上游通过 `removedTagCodes` 只撤销 `REMOTE` 来源；规则失效或删除只处理对应规则的 `SOURCE_REF`。只要仍有其他有效来源，最终展示的标签就继续保留。
- 完全没有规则、人员关系或历史证据引用的误建标签允许物理删除；已有引用的标签只能停用，避免破坏历史追溯。
- 关键词规则可以删除，并同步清理该规则产生的当前标签关系。结构化规则集只有 `DRAFT` 可删除；发布过的版本保留并通过 `DISABLED` 表示不再生效。
- 指标及已引用枚举选项沿用停用策略。人员无论由上游 `deleted=true` 还是管理端删除都只更新软删除标志；管理端可筛选已删除人员并恢复，不执行级联物理删除。

## Trie 动态更新

规则保存事务发布领域事件，监听器只在事务成功提交后查询全部启用规则、构建一棵新树，再通过 `AtomicReference` 替换旧树。请求线程只读取完整快照，不需要和构建线程竞争同一棵可变树。

当前实现是普通 Trie，从文本每个字符尝试匹配。规则量和文本长度继续增长时，可把索引替换为 Aho-Corasick 自动机，业务服务与数据库模型无需变化。

## 第一版暂不包含

- Redis 缓存。
- 完整 RBAC、数据权限和操作审计流水。
- 分布式任务租约锁。
- 中文同义词、暗语和上下文语义模型。

## 结构化研判模型

关键词 Trie 保留为兼容能力。当前结构化规则支持地区、性别、职业和自定义指标的组合判断，并明确 ALL/ANY 关系。规则新增或修改后既可从规则页重算存量人员，也可由 DolphinScheduler 调用内部重算接口，不依赖人员再次发生变化。

标签管理页的“规则”入口统一跳转到按标签筛选的结构化规则页，不再用旧关键词抽屉承载主流程。审核列表中的“命中依据”来自 `PT_PERSON_TAG_EVIDENCE.MATCH_DETAIL`；旧关键词数据仍回退显示 `MATCHED_KEYWORD`。审核页允许删除单条 `RULE` 结果及对应结构化证据，但已发布规则在下次重算时仍可能重新生成该结果，人工和远程绑定不允许从该入口删除。

查询侧需要补充标签画像与反向研判能力：所有查询和聚合以稳定的标签主键为入口，规则名及单条条件只作为标签生成依据和命中解释，不作为人员查询维度。从标签查看命中人数和人员明细，同时聚合这些人员的其他标签，并允许继续叠加标签及人员属性条件缩小范围。人员正向查标签和标签反向查人员应使用同一套已确认标签口径。

风险类标签禁止规则自动通过，命中结果必须进入人工审核。已审核通过的规则标签在人员不再满足条件时退出当前有效结果，但保留历史证据；拒绝只针对本次规则版本和命中证据，规则实质变更形成新版本后可以重新产生候选。

下一阶段仍只处理人员对象，不扩展为案件、车辆等通用对象平台。人员指标通过受控的指标定义管理数据类型、单位、枚举选项和数据来源，实际数据主要由上游同步或系统生成的 Excel 模板批量导入；前端人工新增仅保留兼容入口。规则集直接属于目标标签，支持字段、运算符、类型化条件值和一层 AND/OR 条件组，不支持运行时规则依赖规则；后续复杂场景优先通过规则版本细化或发布时展开处理。

达梦继续作为事实库，保存指标、规则、审核、标签关系及任务批次。Elasticsearch 作为人员画像查询副本，承载标签组合检索、全文搜索和聚合统计；自定义指标使用固定结构的类型化嵌套值，避免每个指标生成一个动态映射字段。DolphinScheduler 编排数据导入或同步、规则计算、ES 增量索引和周期校准。Trie 仅作为文本包含类条件的匹配组件，不再承担整个规则模型。

设计容量上限仍按人员 100 万以内、启用指标 100 个以内、标签 1000 个以内评估；本简历演示环境主动把单次 Excel 控制在 1 万行、ES 文档控制在 5000 人。人员指标只保存带统计周期和来源时间的当前快照；系统生成宽表 Excel 模板和示例文件，第一行保留稳定字段编码、第二行显示中文说明、第三行开始写入数据。任一单元格校验失败时整批拒绝，未出现在文件中的人员不视为删除。指标编码不可修改，已引用指标和枚举选项只能停用。一个标签仅有一个当前生效规则集，规则命中证据允许多来源共存。

Elasticsearch 接受最终一致性：达梦事务成功提交后，以尽力而为方式刷新受影响人员的单个画像文档；刷新失败只记录告警，不回滚已经提交的事实数据。画像只统计当前有效且已审核通过的标签，拒绝和失效记录仅在达梦保留。首次创建索引、历史数据校准或增量刷新失败时使用全量重建修复，暂不引入消息队列、CDC 和持久化增量补偿。

已确认联调 Elasticsearch 为 `7.16.2`，集群名 `ddp_es`，HTTP 地址 `http://10.3.7.225:9200`；当前测试机器可直接访问且未要求认证。客户端和 mapping 按 ES 7.x 兼容口径实现，连接地址仍通过环境变量注入，不在代码中硬编码。

该 ES 为公司共享服务器，仅用于学历和简历项目验证。项目只创建带固定项目前缀的独立测试索引，不修改集群级配置、索引模板或现有业务索引；索引采用 1 个主分片、0 个副本和较低刷新频率，演示数据默认控制在 5000 人以内。ES 数据必须能从达梦重建，清理前先按前缀列出实际索引，再按精确索引名删除，禁止应用自动清理和通配符删除。
