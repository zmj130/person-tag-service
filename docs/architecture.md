# 架构与关键取舍

## 数据职责

达梦是事实数据源：人员资料、标签定义、规则、人员标签关系、同步批次和游标全部以数据库为准。Trie 只是启用规则的内存索引，服务重启后可从数据库完整重建。

```text
DolphinScheduler -> 内部同步接口 -> 远程人员 HTTP API
                                      |
                                      v
                               单页事务写达梦
                                      |
                         +------------+------------+
                         |                         |
                    外部标签绑定              Trie 规则匹配
                         |                         |
                         +------------+------------+
                                      v
                                人员标签关系
```

## 为什么第一版不用 ES

第一版的查询条件固定，主要是人员字段模糊搜索和标签 AND/OR 组合，达梦通过关系表、索引和分组查询即可完成。引入 ES 会额外产生数据同步、最终一致性、失败补偿和索引重建问题。只有数据规模或全文检索性能达到明确瓶颈后，才增加 ES 作为检索副本，达梦仍是事实库。

## 同步一致性

- DolphinScheduler 生成稳定 `batchNo`，重复调用成功批次直接返回原结果。
- 使用远程游标分页，不依赖两台服务器时钟一致。
- HTTP 拉取发生在事务外，每一页写入及游标推进在同一个新事务中。
- 页面失败时整页回滚；已成功页面的游标已经提交，重试从最新游标继续。
- `PT_PERSON.EXTERNAL_ID`、`PT_PERSON_TAG(PERSON_ID,TAG_ID)` 和批次号都有唯一约束。
- 当前代码的 `synchronized` 只避免单实例并发。生产 DolphinScheduler 工作流最大并行度必须设为 1；多实例部署时应再增加数据库租约锁。

## 标签来源和优先级

| 来源 | 默认状态 | 含义 |
|---|---|---|
| `MANUAL` | `APPROVED` | 管理人员明确绑定 |
| `REMOTE` | `APPROVED` | 上游系统下发 |
| `RULE` | `PENDING` 或 `APPROVED` | Trie 关键词规则生成 |

人工/远程已确认标签不会被规则覆盖。人工拒绝的规则候选保留为 `REJECTED`，防止下一次同步反复生成。人员资料发生变化时，已经不再命中的非拒绝规则标签会被删除。

## Trie 动态更新

规则保存事务发布领域事件，监听器只在事务成功提交后查询全部启用规则、构建一棵新树，再通过 `AtomicReference` 替换旧树。请求线程只读取完整快照，不需要和构建线程竞争同一棵可变树。

当前实现是普通 Trie，从文本每个字符尝试匹配。规则量和文本长度继续增长时，可把索引替换为 Aho-Corasick 自动机，业务服务与数据库模型无需变化。

## 第一版暂不包含

- Redis 缓存和 Elasticsearch 检索副本。
- 完整 RBAC、数据权限和操作审计流水。
- 分布式任务租约锁。
- 中文同义词、暗语和上下文语义模型。
